# Acquire and install components

Select the connection before acquiring components. Exploration may query `latest`; an application,
image, or desktop distribution must record exact versions in a lockfile and compatibility manifest.

## Contents

- Discover current releases
- Acquire Univer CLI
- Acquire the agent entry and Runtime Skills
- Acquire daemon/Gateway
- Acquire the Cowork SDK
- Select a distribution model

## Discover current releases

```bash
npm view univer-cli dist-tags.latest
npm view @univerjs-pro/cowork dist-tags.latest
npm view @univerjs-pro/cowork@<cowork-version> peerDependencies --json
```

Treat these results as candidate versions. Do not let production builds track `latest`
continuously. Record at least:

- the `univer-cli` version;
- the CLI Runtime Skill source;
- the `@univerjs-pro/cowork` version;
- the complete Cowork `peerDependencies` object and every resolved version;
- the target OS, CPU architecture, and Node.js version.

## Acquire Univer CLI

For local exploration, install one explicit version globally:

```bash
npm install -g univer-cli@<cli-version>
univer --version
```

When an application, service, or image owns the runtime version, install CLI in a dedicated runtime
dependency root and resolve its absolute entrypoint from the host:

```bash
npm install --save-exact univer-cli@<cli-version>
node ./node_modules/univer-cli/bin/univer.js --version
```

Use the host's existing package manager and lockfile. Persist the resolved executable path and
launch it with an argv array. Desktop and offline products may install the dependency during the
build and package the complete verified runtime.

The CLI npm package includes the `univer` executable, daemon/Gateway assets, and version-matched
Runtime Skills. Gateway does not require a separate service package.

## Acquire the agent entry and Runtime Skills

Install the public discovery Skill so Codex, Claude Code, or Cursor can discover Univer CLI:

```bash
npx skills add dream-num/skills
```

A public product may pin a `dream-num/skills` revision, or prepare the discovery Skill from the
`skills/univer-cli` directory bundled in its pinned `univer-cli` npm artifact. With source-repository
access, it may also record the `dream-num/univer-cli` source commit and canonical
`packages/skills/skills/univer-cli` path. Regardless of how the entry Skill is installed, load
operational commands and Facade workflows from the current CLI:

```bash
univer skills get core --full
univer skills get <sheet|doc|slide|base|board|embed>
```

Never use Runtime Skills generated by a different CLI version as the command authority.

## Acquire daemon/Gateway

Daemon and Gateway are included in `univer-cli`. After resolving the executable, `UNIVER_HOME`, and
listen configuration, start the service:

```bash
univer daemon start
univer daemon status --json
```

Read the actual Gateway origin and external Viewer handoff URL from structured output rather than
assuming a port. The origin passed to Cowork must resolve to the same Gateway from the browser's
network environment. A service or container distribution persists `UNIVER_HOME`, checks daemon and
Gateway state in readiness, and calls `univer daemon stop` when its owner exits.

Derive readiness fields from the installed version's real `daemon status --json` output. The
minimum check shared by current public builds is `daemon.state == "running"` and a non-empty string
at `collabGateway.origin`. Some released builds also return top-level `ok` and
`collabGateway.ok`; consume those fields only when the observed output contains them. Generate host
DTOs and assertions from real output and probe again after upgrades.

Service-created remote targets are returned as Univerfile Links:

```bash
univer new --service <gateway-origin> --name <name> --json
univer import --file <source> --service <gateway-origin> --name <name> --json
```

Persist the returned Link and use that same target in later CLI commands.

## Acquire the Cowork SDK

Cowork is a separately published browser ESM package. A new npm host can let npm resolve the peer
set declared by the selected version:

```bash
npm install --save-exact @univerjs-pro/cowork@<cowork-version>
npm ls --all
```

Existing pnpm, Yarn, or other package-manager repositories keep their current tool and lockfile and
install the complete peer object through that tool. Do not install only the first missing package
from an error or hand-pick a subset of Univer packages. The host supplies Cowork's React, RxJS,
`@univerjs/*`, and `@univerjs-pro/*` peers as one exact, unmixed Univer SDK cohort. `npm ls --all`,
or its equivalent, must report no missing or conflicting peers.

Inspect release metadata after installation:

```bash
npm view @univerjs-pro/cowork@<cowork-version> exports --json
npm view @univerjs-pro/cowork@<cowork-version> peerDependencies --json
```

Then inspect the local `node_modules/@univerjs-pro/cowork/package.json`, `.d.ts` files, and host
lockfile to verify the resolved result against the candidate compatible set. Preserve the complete
`peerDependencies` object and each corresponding resolved lockfile version in the compatibility
manifest, not only one SDK label. For an application that already uses Univer SDK, compare the
React/RxJS ranges and every Univer peer first. If versions are mixed, upgrade Cowork and the SDK as
one set and repeat Viewer acceptance; do not silently overwrite compatibility versions in the
existing application.

## Select a distribution model

| Runtime shape | Acquisition and delivery |
| --- | --- |
| Builder workstation exploration | Install an exact CLI globally; install the discovery Skill as needed |
| Backend or task process | Pin CLI in the project; resolve its executable and manage the subprocess from the host |
| Daemon HTTP service | Pin CLI in the project or image; persist `UNIVER_HOME`; run the daemon |
| Browser host | Pin Cowork and the full SDK peer cohort; connect a browser-reachable Gateway |
| Desktop or offline application | Preinstall CLI, Skill, and Cowork at build time; package them with compatibility and provenance metadata |

Run minimum probes before writing domain code. For CLI, run `--version`, `doctor --json`,
`daemon status --json`, and `skills get core`. For Cowork, import the real packages, typecheck the
host, and load one Gateway snapshot.
